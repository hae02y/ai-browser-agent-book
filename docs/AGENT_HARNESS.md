# AI 브라우저 책 제작 하네스

기준일: 2026-11-27. 이 문서는 이 책의 조사, 개정, 검수, 게시를 여러 에이전트가 이어서 수행하기 위한 작업 계약이다. [작업 대기열](WORK_QUEUE.md)에 실제 진행 상태를 기록한다.

## 목표와 경계

- 독자: 개발 경험이 없는 실무자. 브라우저나 컴퓨터 화면에서 AI가 무엇을 관찰하고 어떤 행동을 실행하는지, 사람은 어디에서 승인하고 어떻게 결과를 확인하는지 이해할 수 있어야 한다.
- 원고: `pages/00`부터 `pages/19`까지의 기존 초안이 출발점이다. 제목의 범위에 맞춰 데스크톱·모바일 장을 보강하며, 새 책이나 새 저장소를 만들지 않는다.
- 범위: 화면을 읽고 클릭·입력·스크롤하는 작업, 실행 환경, 실제 업무, 권한, 검증. 웹 브라우저를 기본 사례로 쓰되 데스크톱·모바일 UI와 다른 제약을 독립적으로 설명한다. 하네스 일반론과 Pickle 사용법은 필요한 만큼만 연결한다.
- 사실: 제품 기능은 공식 문서와 확인일로 뒷받침한다. 모델의 제안과 실행기의 실제 행동, 브라우저 조작과 데스크톱 조작, 픽셀 기반 관찰과 페이지 요소 기반 관찰을 구분한다.
- 실습: 실행하지 않은 절차는 재현 가능한 예시로 표시한다. 실제 성공·성능·안전성을 검증한 것처럼 쓰지 않는다.

## 순서와 담당

| --- | --- | --- | --- | --- |
| 0 | 총괄 편집자 | 기존 원고·독자·목표 | 작업 대기열, 장별 담당과 완료 정의 | 담당 파일이 겹치지 않고 공식 근거 확인일이 정해짐 |

| 2B | 업무·안전 집필자 | 07~13장, 자료 장부 | 07~13장 개정 | 입력·로그인·승인·인젝션·복구·완료 증거를 연결함 |
| 2C | 실습·운영 집필자 | 기존 14~19장, 앞선 장 | 14~18장 개정, 재현 가능한 15장 실습, 전망을 21장으로 이동 | 실행 환경, 절차, 예상/실측 결과, 정리 단계가 구분됨 |

| 3A | 표지·로고 제작 에이전트 | 책 제목·독자·그림 톤 | 전용 원본 표지·로고, `README.md` 표지, 이미지 원장 | 한글 제목 정확성·독창적 로고·썸네일 가독성·파일 크기/경로 확인 |
| 3 | 이미지·권리 검토자 | 본문과 `assets/` | 이미지 목록, 캡션·대체 텍스트·권리 확인, 필요한 도식 수정 | 본문과 그림이 일치하고 출처·개인정보 문제가 없음 |
| 4 | 독립 사실·독자 검수자 | 최종 원고·원문 링크·대기열 | 장별 오류·누락 보고서 | 작성하지 않은 장을 대조하고 중대한 오류가 해소됨 |
| 5 | 총괄 편집자 | 검수 보고 | 통합 원고, 중복 제거, 상태 기록 | 아래 게시 게이트를 모두 통과함 |

2A·2B는 파일이 겹치지 않아 병렬로 진행할 수 있다. 2C·2D는 앞선 장의 표현과 실습 경계를 확인한 뒤 진행한다. 3A는 생성→시각 검수→원고 반영 순으로 수행하고, 4가 표지·로고를 포함해 독립적으로 확인한다. 각 역할은 담당 파일만 수정하고, 인계 시 변경 파일·공식 근거·확인하지 못한 내용·실행한 검증을 남긴다.

## 장별 완료 기준

각 장은 다음 다섯 가지를 갖춘다.

1. 독자가 아는 업무 장면과 이 장에서 답할 질문.
2. 기능·기술에 대한 정확한 설명과 제품별 차이가 있다면 공식 근거·확인일.
3. 사람이 승인할 행동과 에이전트가 스스로 진행해도 되는 행동의 경계.
4. 클릭이나 완료 메시지와 실제 결과를 구분하는 확인 방법.
5. 그림의 설명·캡션·출처 및 실행하지 않은 실습의 표시.

표만 추가하고 독자의 행동을 설명하지 않거나, 제품 발표를 실제 검증 결과처럼 쓰면 완료로 보지 않는다. 각 장의 변경 이유와 남은 의문은 [작업 대기열](WORK_QUEUE.md)에 남긴다.

## 독립 검수와 게시 게이트

검수자는 먼저 공식 원문과 날짜, 목차·상대 링크·이미지 경로, 표지 제목·로고의 정확성, 장 사이의 용어 일치, 개인정보·계정·결제 사례의 승인 조건, 실습의 재현 가능성을 확인한다. 표지·로고에는 외부 회사의 상표가 섞이지 않았는지, 실제 제품 화면처럼 보이는 요소가 없는지, 썸네일에서도 제목이 읽히는지 확인한다. 심각한 사실 오류나 존재하지 않는 화면·기능이 있으면 작성 역할로 되돌린다. 통과 후 총괄 편집자가 문체와 중복을 통합한다.

위키독스 [GitHub 책 만들기 안내](https://wikidocs.net/321336)에 따르면 새 위키독스 책을 만들 때 **기존 GitHub 저장소도 선택**할 수 있다. 현재 저장소가 이미 위키독스 책에 연결되어 있다고 가정하지 않는다. 게시 담당자는 기존 저장소 선택·권한·연동 성공을 확인하고, 검수된 원고를 게시한 뒤 실제 공개 화면에서 목차·본문·SVG·링크·표지 이미지를 확인한다. 위키독스의 책 표지 설정이 README 이미지와 별도라면 `assets/computer-use-ai-cover.png`를 책 표지에도 지정하고 실제 목록에서 확인한다. 게시 완료 전에는 `docs/STATUS.md`에 완료라고 적지 않는다. 오류가 있으면 마지막 정상 커밋을 기준으로 복구하고 공개 화면을 다시 확인한다.
